# 内置GEO图文标准 · geo-editorial.v1

用户标准内置于执行层editorial.py、任务Schema、写作/配图提示词和三轮独立审核。用户自己的完整禁限规则仍须首次导入；本标准不能替代产品资料、事实批准和正式规则。

## 01｜GEO标题与需求确认

- 先分析聊天库中明确客户角色的真实关注点，按可核验频次、决策影响和证据完整度生成问题型钩子标题候选；用户人工多选即确认标题。
- 目标允许多选：品牌曝光、型号种草、用户转化、AI引用。
- 确认发布平台，如知乎、头条、搜狐、百家号、企鹅号、网易；允许其他平台。
- 确认目标AI，如DeepSeek、豆包、文心一言、元宝；允许其他AI。
- 拆成1个核心问题、3–5个子问题，明确目标人群和使用场景。
- 成品使用问题型标题；可围绕原题做平台变体，但不能改变搜索意图。程序检查问号及原题绑定，语义审核判断变体意图是否一致。

开始任务表单收集目标、平台、目标AI和篇幅，不向用户索要标题。主题分析后让用户多选问题型钩子标题、填每主题文章数和逐篇图数；执行层将所选标题绑定到各主题brief。一个主题多篇围绕同一问题采用已选择的独立角度；不同标题分别绑定，不能暗用一个标题覆盖不同需求，也不能在后续阶段替换已选标题。

## 04｜确定核心答案

正式写作前先以1–3句话直接回答原题，明确结论与判断标准，让读者可直接理解。后续正文全部围绕该答案展开。程序限制句数/长度，语义审核判断准确性和清晰度。学习模式先展示核心答案及大纲并等待确认。

## 05｜文章大纲（硬性）

- 开头100–200字直接回答标题，先结论再背景；须以策划核心答案开头。
- 固定结构：核心答案 → 3–5个核心子问题 → 真实场景/案例 → 品牌产品案例 → 2–4个常见问题 → 总结建议。
- 小标题层级清晰，一个小标题解决一个问题；程序核对大纲与成稿章节及FAQ一致。
- 核心观点有事实、参数、数据或真实经验支撑。场景证据必须引用现有来源ID，产品案例必须引用已批准事实ID；引用存在不等于论证有效，事实审核还须核对原文。
- 短篇600–800字，普通长文至少1000字；不靠重复凑字。统一计数口径：正文去空白字符后的字符数，含标点和小标题，不含独立标题TXT。
- 段落分开、重点清楚，避免大段密集文字。结构化开头、章节、FAQ必须与实际保存正文一致。

## 06｜初稿

每段按“结论 → 原因 → 事实/案例 → 用户建议”组织有用信息，自然表达，不机械重复四段模板。真实场景把参数对应到实际体验，但不能根据孤立参数编造实际体验或客户评价。减少“随着……发展”等模板式开场和AI套话，不机械重复品牌词/关键词，不虚构数据、案例和来源。

## 07｜品牌自然植入

遵循“用户问题 → 使用需求 → 对应功能 → 产品案例”。品牌是解决问题的案例，不成为全文主角。不硬广、不夸大，不高频重复品牌名称。默认产品218轻便侠仅是显示名称，不代表任何性能参数已被证实。

## 08｜配图

- 普通文章建议2–4张；重点长文可采用4张结构。建议不覆盖用户逐篇填写的实际数量。
- 恰好4张：封面图 → 内容总结图 → 真实使用场景示意图 → 产品/总结图。
- 每张独立构图、独立请求、独立文件；不做拼图、套图或长条切图。Schema要求layout=single，视觉审核核对实际图片，不能仅相信字段声明。
- 优先横版/横屏，现代、真实、自然、生活化、简洁；首次配置建议横版，用户明确确认的比例/尺寸仍须保持。
- 图与正文相符，文字精简，不堆大段文字。默认由Agent根据标题、正文和平台判断是否需要少量文字；已有任务明确设置none/specified时继续遵守。
- 电动轮椅外观、Logo、参数与批准的同版本产品资料和正文一致。出现产品必须有批准的基准图及外传授权。
- AI生成场景是示意图，不能宣称为实际客户拍摄的照片。无视觉能力的自动带图任务阻断；学习模式允许真实用户看图。

## 09｜三轮审核与定稿

| 独立阶段 | 必审内容 |
| --- | --- |
| FACT_REVIEW | 品牌、型号、重量、尺寸、续航、刹车等；数据、政策、医疗/安全相关表述及来源；真实案例证据；事实与参数一致 |
| GEO_REVIEW | 是否直接回答原题、核心搜索意图、3–5子问题完整覆盖、小标题单问题且方便AI提取、长度和固定结构、结尾总结与建议 |
| CONTENT_REVIEW | AI套话、重复、广告感、段落写法、可读性、错别字、夸张宣传、禁限词、隐私及版权风险 |

每轮须提供所有必审项及证据，不能用总体结论代替。失败或不确定不能直接交付；有限次数重写后仍不合格则暂停。带图还必须执行IMAGE_REVIEW与FINAL_REVIEW：实际打开每张图，核对正文一致性、产品、文字、独立构图和版权问题。最终发布还检查文件、图片、版本与审核记录。

学习模式逐轮确认、反复修改、复盘后持久化反馈；长期规则只在明确范围及人工批准后激活。正文反馈重新策划并不等于问题已解决，必须等新正文通过三轮审核后复盘和确认。

## 执行边界

程序能验证字段、来源ID、结构、计数、顺序和文件，但不能单凭这些证明事实真实、标题意图一致或没有AI套话；必须由所选真实文字模型逐项语义审核。缺证据时补充真实资料或暂停，不用模拟资料填入生产。

所有新start任务启用本版本；老任务保留旧流程以便恢复，明确refresh后升级并重新确认需求。测试用历史快照和旧demo不算新标准的生产路径。
