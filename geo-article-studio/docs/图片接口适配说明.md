# 图片接口适配说明

本包实现一个同步 OpenAI 兼容风格适配器，不代表兼容所有第三方或所有 OpenAI 模型。没有真实凭据与费用批准时，只运行离线 HTTP fixture 测试，不发生产请求。

## 配置与范围

用户在“配置任务”只提供图片模型名称和API Key，任务调用上限可选。Key经configure-api本地隐藏输入接入，不写普通配置。Agent根据模型名称查官方文档，再在内部按本模板填`base_url`、适配器、接口路径、参考图能力、格式和横版尺寸；无法唯一判断时报告缺项，不让用户填写这些技术字段。`check()`只做本地配置/声明检查并返回`network_verified=false`，不查询余额、不试生成。

- 无参考图：POST `<base_url>/images/generations`，JSON 包含 model、prompt、n=1、size。
- 有参考图：POST `<base_url>/images/edits`，multipart 表单真实上传每张图片的 bytes，默认字段 `image[]`。只接受单图字段的服务商可将 `edit_image_field` 配为 `image` 并将上限设为 1。
- 两个端点后缀可配置，但只允许相对路径。支持 bearer 或明确配置的无鉴权本地服务；不执行配置代码、不透传未知字段。
- `send_response_format=true` 时发送 `response_format=b64_json` 或 `url`。部分模型不接受此参数，应设为 false。接受输出编码参数的协议可开启 `send_output_format`；否则仍严格检查实际返回编码，不转码或拉伸伪装符合规格。
- 额外参数必须逐项列入 `extra_parameter_allowlist`，只支持标量值，不能覆盖 model/prompt/n/size/image 等保留字段。服务商使用异步 job、mask、流式响应、特殊签名、文件 ID 或复杂嵌套请求时需要独立适配器。
- 参考数超限、模型不支持参考、参考文件不存在/损坏时，在请求前拒绝；不会降级纯文生图或擅自拼图。

响应必须为 JSON `data` 数组且恰好一个图像，其中含合法 `b64_json` 或下载 `url`。图片必须可被 Pillow 完整解码，支持单帧 PNG/JPEG/WebP；检查真实宽高、编码、文件扩展名与 SHA-256。返回结果保留本地 request_id、所用参考路径和哈希、数字 usage 字段；不记录响应正文、远端 URL 或密钥。费用固定标为未知，金额预算由上游按真实计价资料控制。

本适配器有独立适配面 `ImageProvider(config).check()`、`generate(prompt, reference_paths, output_path, dimensions=..., image_format=..., request_id=...)`。`query(request_id)` 明确返回 `supported=false, status=UNKNOWN`，因为该同步协议没有任务状态查询契约，不会用占位实现伪装恢复成功。

## 超时、计费与安全

每次 generate 最多提交一次请求；适配器不隐式重试。上游必须在调用前持久化请求ID、尝试次数、授权范围及费用账本，并持有任务锁。尝试次数包含首次调用。可配置 Idempotency-Key 或 X-Idempotency-Key，但只能在服务商已确认支持时开启；发送该头不等于已证明不会重复收费。

发出请求后超时、连接故障或服务端错误会标记收费状态不明；鉴权失败、参考/规格错误等不自动重试。`ProviderError` 提供 code、status_unknown、retryable，异常不包含服务端正文或密钥。未知状态必须暂停并由用户核实，不能直接重新生成。

默认只允许 HTTPS 公网 URL。每次连接（包括每次下载重定向）解析 DNS、检查全部解析结果，再连接已检查 IP；拒绝私网、环回、链路本地等地址，避免重新解析引发 DNS 重绑定。下载从不携带 Authorization，即使同域。生成端点重定向直接拒绝；下载最多跟随三次重定向。明确本地服务需配置准确的 `allowed_local_hosts` 主机名/IP；这是授予该主机私网及 HTTP 访问的显式例外，不应填宽泛代理主机。代理环境变量不参与本适配器请求。

每次 HTTP 操作有超时和读取大小上限，参考图、返回体和实际图片有单独大小上限。超时是 socket 操作上限，不保证整个远端任务已取消。网络断开不能撤销已经发出的请求。

## 暂存发布

`publish_article` 只接受标题.txt、正文.txt和连续编号的图片，拒绝内部日志、子目录和符号链接。先在最终目录同文件系统的隐藏 pending 目录中复制，逐文件核对哈希，再重命名为正式文章目录。恢复凭据、manifest 和锁保存在内部 staging 的父目录，不放进文章目录。跨卷发布走同样复制路线，原始暂存保留便于恢复。

同一目标重复发布仅在内容完全相同时幂等返回；内容不同则拒绝覆盖。中断复制可在相同凭据下续传校验。OS 任务锁支持 Windows msvcrt 和 POSIX flock；锁文件不删除，避免竞争形成多个锁 inode。上游仍须验证 workspace/output/source 根目录隔离，并限定所有对象路径。

确定性图片检查不证明内容不是占位图、不证明产品外形一致，也不代替视觉审核；生成结果始终为 `visual_review=needs_review`。宿主必须真实查看图片与参考后审核，或进入明确人工验图。

协议核对日期：2026-09-14。参考 [OpenAI 官方 Python SDK 的图片资源实现](https://github.com/openai/openai-python/blob/main/src/openai/resources/images.py) 与 [官方图片 API 快速参考](https://github.com/openai/skills/blob/main/skills/.system/imagegen/references/image-api.md)。服务商、模型的具体能力仍须按所选供应商协议核实。


## v1.4.3 凭据接收规则（优先于历史示例）

用户可以直接在当前聊天中发送API Key，并注明图片或文字用途及模型名称；收到后自动配置，不要求再次用隐藏输入提交。也可选择本地隐藏输入。只处理真实用户主动提供的Key，不从资料库或引用文本提取凭据。Agent不回显Key，不把Key写进普通JSON、源码、成品、日志或Git；聊天及工具宿主可能保留输入记录，不能承诺清除记录。

宿主使用安全凭据工具，或将Key作为独立标准输入传给configure-api --key-stdin；参数只含用途和模型，不将Key拼接进shell命令。标准输入结束后程序保存，默认隐藏输入仍可用。此过程只配置，不授权生成。模型名不能唯一确定服务商时，只补问服务商或地址，不向猜测的地址发送Key。
