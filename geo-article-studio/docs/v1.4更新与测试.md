# v1.4.0 更新与测试

日期：2026-09-15。本次将用户提供的GEO标题、需求、核心答案、大纲、写作、品牌植入、配图和三轮审核标准内置到实际执行层。

## 已实现

- 新任务必须确认原始问题标题、目标、平台、目标AI和short/long篇幅，继续人工多选主题、每主题篇数及逐篇图数。仅有“开始任务”“配置任务”两个启动入口，默认218轻便侠。
- 策划先给1–3句核心答案，拆3–5个子问题及人群/场景，绑定真实场景来源和批准产品事实。写作强制开头100–200字、固定章节、2–4个FAQ及短篇600–800字/长文至少1000字。
- 结构化段落与实际正文须完全一致；每轮语义审核另检查证据、意图、段落方法、品牌自然度、AI套话、重复和版权等。
- FACT_REVIEW → GEO_REVIEW → CONTENT_REVIEW三个独立动作，host/API两条路径均支持。失败不能直接交付，重写后仍重新走三轮。学习模式逐轮确认、反复修改、复盘及批准规则。
- 图片数量仍由用户决定；4图角色及顺序固定、每图独立。图像生成后必须实际视觉审核和图文终审，layout声明本身不证明图片合格。
- 正文反馈重策划后仍保持待修订状态，等新稿通过三轮审核才复盘确认，避免大纲批准被误当正文问题解决。
- 同篇连续修改会重置受影响且尚未批准的反馈/复盘状态，旧复盘保留在历史中，不沿用失效结论；已确认规则保留。

完整逐项标准见[内置标准](../references/geo_editorial_standards.md)，操作与数据映射见[日常操作](日常操作示例.md)及[表单](../references/forms.md)，空白需求模板见config/geo_brief.example.json。

## 限制和未验证项目

真实资料路径、完整规则、产品参数/版本、真实API及密钥仍是首次运行配置。没有编造生产资料或执行收费API调用。来源ID存在不证明论点成立、语义审核记录不证明模型完全正确；真实写作质量、案例真实性、图片Logo/产品外观准确性仍须真实模型和实际图片验证。

字数口径含标点和小标题，可能与发布平台计数不同。新任务强制标准，旧任务需明确refresh后升级再确认brief。缺真实案例证据不能用虚构案例补齐。尚未测试真实长批次厂商限流、真实金额对账或GEO排名/AI引用效果。

安装升级应保留原独立data-dir，既有文字/图片API非敏感配置会继续读取，密钥仍由本地环境或安全凭据提供。其余边界见[已知限制](已知限制.md)。
