# 日常操作示例

下列自然语言示例是用户与宿主Agent的操作方式。T01/T03只表示实际分析后返回的编号，不能作为硬编码主题。脚本由宿主Agent调用，不让用户逐项编写模型JSON。

## 首次设置

用户：`/geo-article-studio 配置任务`

助手直接展示程序返回的中文表单（form 配置任务 --format text），218轻便侠预填。表单含产品、四库与保存位置、有图任务才需的图片API，以及可选文字API；每项标明已保存、默认、本次填写或待补充，只需回复要补充/修改的内容。配置任务不再询问最少/最多字数，开始任务选择短篇600–800字或普通长文至少1000字。

用户填写真实路径，Agent验证当前运行机器实际可读；远程路径必须显式映射。允许部分configure合并保存，不清空未修改字段。保存后告诉用户配置路径、已保存项、本地接口检查及凭据接入状态，缺某类API只影响相应任务，不假称联网验证通过。index查看实际已解析/失败/排除范围，不能把未解析PDF称已读。

产品信息注册使用明确product_id/name/version及source_mappings，不能按文件名“218”自动归属。`products extract --product-id ID`提取事实候选；自由文档也可由当前模型提交`products candidates --file FILE`，每条须quote/source_id。展示后才`products approve --fact-id ID --user-input 确认`。冲突先展示全部来源，`resolve-conflict`明确选用事实及拒绝竞争事实。

用户在同一次配置表里只填写图片模型名称，并通过本机隐藏输入提供 API Key；每任务图片调用上限可填可不填。Agent查找官方文档，核对并保存地址、适配器、接口路径、参考图能力、格式和横版尺寸。图片是否带少量文字、是否展示产品由每篇标题、正文和已批准产品资料自动决定。参考图索引结果显示source_id/hash，用户批准所选图片及传输范围后记录image_authorizations。文档无法核实时先保存模型和凭据，保持技术配置门禁，不猜兼容性或发付费探测。

完整禁限规则随技能内置；已进入任务后可要求更新学习规则。外部非结构化词表如需追加，由当前模型整理候选并经用户核对后导入正式JSON，记录原始资料与整理版本。示例词表不能用于正式生产。

## 学习模式：修改、复盘、确认

1. 用户：`开始任务`，然后选择学习模式和本次文字来源（默认模型/已配置第三方API），产品218轻便侠。缺版本时只问版本，缺资料则停在预检。
2. 助手预检并展示产品理解、资料缺项和范围，用户：`确认下一步`。真实用户输入绑定当前action_id/revision。
3. 助手分析聊天给主题候选与来源。用户：`选T01，文章1篇，每篇1张图`。随后确认该主题原始问题标题、目标、平台、目标AI及short/long篇幅；开始表单已有值则复用用户确认值。内部brief映射见references/forms.md。
4. 助手展示当前文章策划。用户：`修改：这篇更简洁，不要人物`。
5. `revise`保留旧结果、写feedback和proposed规则；当前模型修改当前策划，复审并说明：本次问题是表达冗长/人物安排与用户意图不符；措施是缩短结构并限制本篇画面。建议规则scope=article，绑定当前task_id/article_id，不推广全局。修改后仍停当前步。
6. 修改后先完成LEARNING_REVIEW结构化复盘，再让用户确认新策划；若同时明确同意该规则，`approve --rule-ids ...`激活，否则只批准当前结果。随后正文生成→事实检查及人工确认→GEO检查及人工确认→内容合规检查及人工确认；配图计划和真实参考→确认；实际生成图及视觉审核→确认；联合终审→确认。正文反馈会回到策划，但等新稿通过三轮审核才复盘和确认解决。
7. `export`整篇发布后，助手只输出实际成品目录绝对路径。没有真实图或未通过视觉审核不得输出成功路径。

## 自动模式：多主题与不同数量

1. 用户：`开始任务`，然后选择自动模式和本次文字来源。产品218轻便侠预填，聊天分析之后仍等待人工选题。
2. 用户：`T01写2篇，各3张图；T03写1篇，2张图`。
3. 助手汇总3篇8图，逐主题核对原始GEO问题标题、目标、平台、目标AI及short/long篇幅，并把人工确认的brief连同topic_id/article_count/image_counts提交。前置规格、正式规则、参考授权和请求上限齐备后，这次提交即授权当前任务生产。
4. 当前宿主循环next-action→当前模型→submit-result、run-image、export。普通阶段不额外问继续。单篇独立角度不够、事实冲突、缺视觉能力、UNKNOWN收费、次数上限或文件异常时暂停；不能偷偷改篇数/降级参考图。
5. 全部3篇和8张实际图校验后只返回真实根目录。每篇独立文件夹，标题.txt、正文.txt、配图文件分离，内部审计留workspace_root。

## 暂停、续跑与规则复用

`暂停任务`保存当前状态，不再发起新请求，已经发出的请求可能仍收费。`继续任务＋任务编号`经resume校验文件/hash，不重复生成已合格图片。UNKNOWN必须先核对服务商状态；确认失败的请求计入上限，不能抹掉旧尝试。

`查看规则`展示生效规则及版本；新任务复用product/global/style规则，article/topic限定原任务。正文实质修改会使关联配图失效；成品修改用fork-revision另建任务保留旧输出。配置/资料/规则变化使用refresh重新分析，不混用快照。

第三方文字服务可在配置任务中提前设置并长期保留；开始任务每次仍需选择来源。实际步骤见[文字模型配置与选择](文字模型配置与选择.md)。

新文章自动遵循[内置GEO标准](../references/geo_editorial_standards.md)，先1–3句核心答案，再按固定结构写稿。普通文章2–4图仅是建议，不改用户数量。恰好4图依次为封面、内容总结、场景示意、产品/总结，独立生成和保存。缺真实场景证据或产品事实会要求补证；不编造案例维持流程。
